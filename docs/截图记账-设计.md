# 截图记账：设计与实现说明

> **当前状态：入口已关闭。** `App.tsx` 的 `SHOW_SCAN = false` 不渲染顶栏相机按钮；识别链路、本机 OCR 与 122 项单测全部保留，改回 `true` 即可恢复，无需动其他代码。关闭原因：真实账单截图的版式差异仍会漏读（见第三节末），使用体验还没打磨到位。入口关闭后整个 `src/scan/` 会被 tree-shaking 移出产物，应用体积回到功能开发前的基线。

> 入口：顶栏相机图标（移动端在 `.topbar-right`，桌面 ≥820px 在 `.side-actions`，同一按钮常量复用）。
> 代码位置：识别内核 `src/scan/`，UI `src/components/ScanModal.tsx`。

## 一、为什么是这个形状

口袋记账是 100% 静态站点（GitHub Pages，无后端、无 serverless、无法保管密钥）。同时项目对「数据不出本机」有明确承诺。两条约束合起来决定了设计方案：

**金额提取处理的是文字，不是像素。** 粘贴账单文字、云视觉模型、未来的本地 OCR，都只是「把图片/剪贴板变成一段文本」的不同上游；下游的归一化 → 金额抽取 → 分类映射是一条完全相同的纯函数链。于是：

- 零网络的粘贴路径是**默认且永远可用**的主路，不是降级方案；
- 任何云端识别都是可插拔 provider，用**用户自己的**端点与密钥；
- 新增本地 OCR 不需要改动任何既有逻辑。

## 二、模块划分

```
src/scan/
  types.ts        契约：ScanProvider / ScanResult / AmountGuess / CONFIDENCE_GATE
  normalize.ts    normText() 全角转半角、货币符号统一、拆行（保留空格，商户标签靠它切分）
  amount.ts       extractAmount() 金额抽取与打分              ← 最容易错的一环
  category.ts     账单自带分类 / 分类名匹配 / 商户 / 日期 / 账户推断
  merge.ts        mergeModelResult() 模型结果 × 本地规则交叉校验
  preset.ts       scanResultToPreset() → 记账面板的 preset
  prompt.ts       视觉模型共用指令 + JSON 容错解析 + chatUrl()
  keyStore.ts     端点与密钥读写（裸 localStorage 键，刻意在 zustand 之外）
  image.ts        canvas 降采样：长边 1280 / JPEG 0.85 / base64 上限
  index.ts        parsePaymentImage() 唯一入口 + 对外再导出
  providers/      text.ts · local.ts（tesseract.js 懒加载）· openai.ts · gemini.ts · probe.ts · index.ts（注册表）
```

数据流：

```
File ─┬─ createObjectURL ─────→ <img> 预览 ──卸载──→ revokeObjectURL
      └─ canvas 降采样 ──→ base64 ─┐
（用户粘贴）text ───────────────────┴→ provider.run → 文本
   → normText → extractAmount / extractDate / extractMerchant
   → ScanResult → ScanModal 核对区（可改金额/类型/分类/账户/日期/备注）
   → scanResultToPreset → Txn{id:'',createdAt:''}
   → App.openFromTemplate → TransactionForm → saveTxn
```

## 三、金额抽取规则（`amount.ts`）

支付截图里绝大多数数字都不是金额，所以这一步的主体是**排除**：

1. **收割**：千分位 / 小数 / 整数三类数字串；两侧紧邻仍是数字的（长连号片段）直接丢弃。
2. **否决**：13 位以上连号、日期、时间、手机号、`20xxxxxxx`；`订单号|流水号|卡号|尾号|手机号` 等标签右侧整段；`余额|积分|优惠|原价|运费|服务费|红包|立减|抵扣` 等标签后 10 字符内；`%`、三位以上小数、紧跟量词（`9月` `15笔`）、括号内数字（卡号尾号）、`7-Eleven` 式品牌 token、**数字后直接粘汉字**（`立即领取20积分`）。
3. **打分**（用于排序）：锚点词强 +10 / 中 +7；紧邻 `¥`/`元` +4；恰好两位小数 +3；**数字前有减号 +6**；OCR 词框字号 ≥1.5 倍中位 +6（≥1.2 倍 +3）；位于上部 +3；**没有任何货币记号的裸整数 −6**。
4. **置信度**用证据叠加而非分数线性映射，便于按误判样本单独调权：基线 0.35，强锚点 +0.3、货币符号 +0.15、减号 +0.15、两位小数 +0.1、大字号 +0.15、靠上 +0.05，上限 0.95。
5. **闸门** `CONFIDENCE_GATE = 0.6`：低于闸门或最高分并列（`ambiguous`）时，UI **不预填金额**，只给候选芯片让用户点选。
6. 边界：`≤0`、`>2,000,000` 拒绝；`1.28万` 换算为 12800 并打 `wan` 旗标。

### 真实截图评测改写的四条规则

规则最初由自造 fixture 调出，但**自造 fixture 的版式是理想化的**（我把状态词写在了金额上方）。拿 8 张真实支付宝/微信账单截图一测，8 条全败，暴露出下面四条只有真实版式才能教给我的事实：

| 事实 | 后果 | 修法 |
|---|---|---|
| 账单详情页版式是「商户 / **-412.00** / 自动扣款成功」，状态词在金额**下方** | 只回看上一行的锚点全部落空，抓到「立即领取**41**积分」 | `findAnchor` 上下双向回退到相邻短标签行 |
| 账单主金额**一律带减号**（`-412.00`），这是比任何关键词都硬的约定 | 未利用最强信号；且「对方已收钱」被误判成收入 | 减号 +6 分、+0.15 置信度，且 `minus` 直接定性为支出 |
| OCR 会**打乱双栏阅读顺序**（先吐完左列标签，再吐右列值），值还带 `＞〉` 垃圾尾字符 | 「账单分类 / 交通出行〉」拆成两行且查表失配 | 分类正则允许跨行 + `trimCategory()` 清洗首尾垃圾 |
| 截图里有未读角标 `<1`、电量 `85分` 这类裸整数 | 「1」凭位置分压过 `¥28.50` | 无 `¥`/两位小数/减号/万 任一记号者 −6 分 |

另有一条分类规则修正：美团那行推广文案「外卖团购特价美食**酒店**电影」会同时命中餐饮与旅行，规则表按序取先命中者 —— 故**餐饮排在旅行之前**，账单里外卖类消费远比真住宿常见。

上述四条均已固化为 `__fixtures__/ocr-scrambled-columns.txt` 等回归用例（**用脱敏假数据重写**，真实截图的 OCR 原文含商户全名、交易单号与金额，不入公开仓库）。


## 四、分类与账户：只认名字，绝不造 id

`createDefaultCategories`（`store.ts:80`）用 `uid()` 生成分类 id，**跨设备完全不同**。所以：

- `matchCategoryByName()` 两段式：① 用户分类名直接出现在文本里（长名优先）；② `CATEGORY_RULES` 关键词表映射到**默认分类名**，再解析回本机实例；③ 都落空返回 `null`，分类留空由用户点选。
- 匹配**按收支类型过滤**。`TransactionForm.switchType`（`TransactionForm.tsx:66`）会在用户改类型时清空分类，所以核对页换方向时会用新方向重新匹配一次。
- 账户同理：只按账户名子串 + 常见别名（零钱/余额宝/储蓄卡/信用卡/花呗）匹配，且限定在当前账本与 `canSelect !== false` 内；命中不到返回 `''`，交给记账面板的默认值。
- 日期识别不到就用今天，**永不返回未来日期**（OCR 误读年月很常见），并拒绝 `2月31日` 这类会被 `Date` 悄悄滚动的假日期。

## 五、识别引擎：本机 OCR 是图片路径的默认选择

`providers/` 下四个引擎，按「是否出设备」分档：

| 引擎 | 图片去向 | 首次成本 | 真实截图金额命中率 |
|---|---|---|---|
| `text` 粘贴账单文字 | 不出设备、不联网 | 0 | 取决于用户能否复制 |
| `local` 本机识别（tesseract.js） | **不出设备** | 下载约 **5.0MB**（core 1.44 + chi_sim 1.69 + eng 1.94 + 胶水），之后走浏览器缓存 | **8/8** |
| `openai` 自定义端点 | 上传到你填的域名 | 0（需密钥） | 最高 |
| `gemini` | 上传到 Google | 0（需密钥） | 最高，但国内网络通常被拒 |

上表的命中率是拿真实支付宝/微信账单截图测出来的：本机同时装了 `tesseract` CLI（与浏览器端同一引擎）和 macOS Vision（与 iPhone 实况文本同一引擎），把两者的 OCR 原文分别灌进这条管线对比 —— **金额字段打平（8/8）**，差距只在日期（8/8 vs 7/8）和分类（6/6 vs 4/6），而这两项识别不出来只是需要手点，不会记错账。所以云端视觉模型对「读金额」这件事是过剩的，`local` 才是图片路径的默认。

三条实现约束，都是实测换来的：

1. **`tessedit_pageseg_mode` 必须是 `3`**。默认的 psm 6 会把账单里最大最粗的主金额**整行漏掉**（反而认出了小字的日期和分类）。
2. **语言包必须 `chi_sim` + `eng` 同时带**。只用 chi_sim 时 8 张截图里有 2 张把数字读错（个位与末位小数各错一处），加 eng 后金额 8/8。数字正是 chi_sim 最弱、eng 最强的地方，而这 2MB 买的是最不能错的一位。
3. **jsdelivr 的 `tesseract.esm.min.js` 只导出 `default`**，没有具名 `createWorker`。直接按具名取会拿到 `undefined` 并在运行时才炸，所以 `pickTessModule()` 两种形状都吃。

引擎与语言包一律 **CDN 动态 import，绝不进 `dist`**：整套约 5.0MB，而应用本身约 117KB gz，打进来会让首屏膨胀数十倍。代价是首次识别需要联网；`workerP` 做模块级单例复用（每次重建 worker 都要重载 5MB，不可接受），取消识别时 `terminate()` 释放。

## 六、云端识别的隐私边界

`README` 承诺数据不出本机，图片识别是唯一例外，因此把它关进笼子的四道锁都在代码里：

1. **默认不联网**：粘贴路径优先，未配置端点时云引擎在 `available()` 阶段就不出现。
2. **逐次同意门**：`ScanModal` 的 `consent` 阶段，每次换图都要重新确认，界面直接显示目标域名（`hostOf()`）。
3. **图片不落盘**：只有 `createObjectURL` 预览与内存里的 base64，卸载即 `revokeObjectURL`；不新增 `Txn` 字段，因此 **persist version 仍是 3、`migrate` 与 `exportJSON` 白名单都不用动**。
4. **密钥不进 store**：端点与密钥写在裸键 `pl.scan.settings` / `pl.scan.apikey`，不经过 zustand persist，因此既不会被每次 `set()` 的全量序列化拖慢，也不会出现在用户分享出去的 JSON 备份里。

> **当前状态（重要）**：设置面板里的「识别与导入」分组已按产品决定整块移除 —— 日常只有「粘贴文字」与「本机识别」两条不出设备的路径，云端配置没有入口，也就不该占常驻菜单。云端 provider 代码（`providers/openai.ts`、`gemini.ts`、`probe.ts`、`prompt.ts`、`merge.ts`、`keyStore.ts` 及其单测）**全部保留且仍被测试覆盖**，只是未接入 UI：因为 `available()` 要求 baseUrl + 密钥，缺配置时它们不会出现在识别弹窗的引擎切换条里。要重新开放，只需在 `SettingsPanel` 加回一个分组去写 `pl.scan.*`（历史实现见该文件的 git 记录）。

模型返回一律过本地规则复算：`mergeModelResult()` 里金额以本地 `extractAmount` 为准，模型自述值只是交叉校验；两者对不上则 `crossCheckFailed` 并把置信度压到闸门之下。模型报的商户名必须在原文里出现，否则按幻觉丢弃。

**Gemini 的网络前提**：Google 按落地 IP 信誉放行，国内直连与多数机场节点会收到 `User location is not supported`。因此 Gemini 只作为第三选项，密钥走 `?key=` 查询串（换成 `x-goog-api-key` 头会触发 CORS 预检），并把地区受限的错误翻译成一句可执行的中文提示。主力是「OpenAI 兼容 + 自填 baseUrl」，可指向国内可达的中转或自建 Worker。

## 七、加一个新识别引擎

1. 在 `src/scan/providers/` 新建适配器，实现 `ScanProvider`：`available()` 判断配置是否齐备，`run()` 把输入变成文本，最后交给 `mergeModelResult()`（纯文本引擎用 `analyzeText()`）。
2. 在 `providers/index.ts` 的 `PROVIDERS` 数组里登记一项。
3. 在 `ScanSettings['engine']` 联合类型与 `keyStore.ts` 的 `ENGINES` 白名单里加一个 id。若该引擎需要配置（密钥/端点），还要在 `SettingsPanel` 加回写入 `pl.scan.*` 的分组 —— 目前设置里没有这个分组，只暴露「粘贴文字 / 本机识别」两个免配置引擎，识别弹窗的切换条会按 `available()` 自动过滤。
4. 下游（核对页、preset、记账面板）**无需改动**。

本地 OCR（tesseract.js）如果将来要做，只能走 CDN 动态 `import()`，语言包用 `4.0.0_fast`（chi_sim 约 1.73MB gz）而不是默认 `4.0.0`（约 20MB），**且永远不要打进 `dist`**：当前应用 JS 总量约 116KB gz，全量本地 OCR 会让首屏膨胀数倍。

## 九、留给 v2：账单附件留档

与路线图既有的「记账图片与位置」合并实现：

- 新建 IndexedDB `pocket-ledger-images`，store `images`，键 `${txnId}:${n}`，值存 **Blob**（不是 base64）。
- `Txn` 增 `attachments?: {name,w,h}[]` 元数据（仅元数据），届时才需要 `persist version 3→4` + `migrate`。
- `exportJSON` 增加附件清单，但图片字节不进 JSON；`importJSON` 按 `txnId` 对账，缺失项丢弃。
- **绝不能把用户图片存进 `pocket-ledger-v*` 命名的 Cache Storage**：`sw.js` 的 `activate` 会删除所有非当前版本的缓存，等于发一次版就清空用户图片。
- 禁止任何二进制字段进 zustand persist：该中间件每次 `set()` 都会把整个 state 序列化成一个大字符串，而 iOS Safari 给单个 origin 的 localStorage 预算约 5MB，一张截图就能撑爆。
